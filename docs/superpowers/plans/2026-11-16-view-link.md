# View link: implementation plan

Spec: this file (agreed in chat on 2026-11-16, after a spike measured link lengths on real data).

## Goal

A chain icon in the page header copies a link to the current view. Opening that link shows the same view: the selected source, the main data mart and the joined marts' columns, the main grid's filters, sorts and row limit, the open record, the Data Marts band search, context badges and storage filter, and which bands are folded. Parts the opener can't see, or that were deleted since, are skipped. The rest still shows, and nothing throws or blocks the page.

## Global constraints

1. The link is a plugin route: `/v?s=<payload>`. The host copies it via `ctx.ui.copyLink(route)` and hands it back on open as `ctx.route`. The host refuses any route longer than **2048** characters. Our cap is the same: `MAX_ROUTE_LENGTH = 2048`, counting the whole route including `/v?s=`.
2. Payload = base64url (no padding) of `deflate-raw` of UTF-8 JSON. Use the browser's `CompressionStream('deflate-raw')` / `DecompressionStream('deflate-raw')`. No new dependency.
3. JSON shape, version 1. Short keys keep the link short:
   ```ts
   type ViewLinkV1 = {
     v: 1;
     P: string[];                 // shared join-path prefixes, see 4
     src: string | null;          // selected source key
     m: string | null;            // main data mart id
     r: Record<string, unknown> | null; // open record's primary key (the record belongs to m)
     q: string;                   // Data Marts band search
     ctx: string[];               // context badge ids
     st: string[] | null;         // ticked storage ids; null = all
     f: { sources: boolean; marts: boolean; data: boolean; row: boolean }; // folded bands
     g: null | {                  // main mart's grid; null = the mart has no grid state yet
       c: Col[];                  // columns, in order
       fl: [Col, string, unknown][]; // filters: field, op id, value (value omitted -> undefined)
       s: [Col, 1 | -1][] | null; // sorts, 1 asc / -1 desc; null = member set none
       l: number;                 // row limit
     };
   };
   type Col = string | [number, string]; // plain name, or [index into P, field suffix]
   ```
4. Shared prefixes: a joined column name has the form `<joinPath>__<field>`, split at the **last** `__`. The join path goes into `P` once, and the column becomes `[i, field]`. Names without `__` stay plain strings. Decoding rebuilds `P[i] + '__' + field`. An index out of range makes that one column invalid (it is dropped, see 6), not the whole link.
5. The route is untrusted input (SDK README: use it only to choose what to show, never to start a write or a run). Opening a link must not write to the member's saved columns or band fold preferences, must not start an export, and must not push an Undo entry.
6. Never throw, never block. Skipping rules, each counted for the notice in 7:
   1. Route isn't `/v?s=…`: not a view link. Open normally, no notice.
   2. Payload doesn't decode (bad base64, bad deflate, bad JSON, `v !== 1`, wrong top-level types, route over 2048): open normally. Notice: "This link couldn't be read. Showing the default view."
   3. Individual malformed entries inside a valid payload (a column that is neither string nor valid `[i, field]`, a filter that isn't `[col, string, value?]`, a sort whose direction isn't 1/-1, a non-string context id): drop that entry only.
   4. Main mart `m` not in `model.marts` or not `accessible`: drop `m`, `r` and `g` (count "data mart"). The page's existing first-load pick applies.
   5. Source `src` not in `model.sources`, or `m` is kept and the mart's `sourceKey !== src`: drop the source (count "source").
   6. Context ids not in `model.contexts`, and storage ids not in `model.storages`: drop those (count each). If `st` ends up empty after dropping, use `null` (all).
   7. Columns, filter fields and sort fields the main mart's schema plus its joined sources don't offer: drop them (count "columns", "filters", "sorts"). The schema comes from `schemas.get(m)` and joined sources from `blendable.get(m)`. If either read fails or takes over `VIEW_LINK_WAIT_MS = 5000`, don't prune grid fields at all: pass them through, since the grid already parks what it can't offer. If every column is dropped, set `g` to null so the grid opens with its defaults.
   8. A filter whose op/value doesn't fit its field is kept. The grid's query builder already skips filters that fail `isComplete` (`src/filters/build.ts`).
   9. Row limit: clamp to `[PAGE_SIZE, PAGE_SIZE * 10]`, rounded to a multiple of `PAGE_SIZE`.
   10. Record `r`: kept only if `m` is kept and `r` is a plain object. If the record no longer exists, `RecordView` already shows "Record not found".
7. Notice: when anything was skipped (6.2–6.7), show one dismissible line under the header. Wording: "Some parts of this link aren't available to you: <items>." Items joined with ", ", in this order, with counts where plural applies: "the data mart", "the source", "N columns", "N filters", "N sorts", "N contexts", "N storages". Use singular for 1 ("1 column"). For 6.2 use the 6.2 sentence instead.
8. While a view link is being resolved, the page shows its loading bar as one more step (like the saved folds read) and does not run the first-load mart pick. After resolving, one `applyView` action sets everything at once.
9. Folds from the link override both the default and the saved folds for this visit and are not written to preferences. A fold the member clicks afterwards is saved as usual.
10. Copying: the chain button (lucide `Link`, size matching the Undo/Redo buttons, `aria-label="Copy link to this view"`, tooltip "Copy link to this view") sits in the header's actions area. It is hidden when `ctx.route === undefined` (host without page links). On click: encode, then `ctx.ui.copyLink(route)`. The host shows its own "Link copied" toast. If the route is over 2048, don't call copyLink; show the notice line "This view is too large to link. Remove some columns or filters and try again." If `copyLink` rejects, show "The link couldn't be copied."
11. Undo history is not in the link. Neither are grids of marts other than the main one.
12. Code comments and UI text follow the repo's existing style: short, plain, sentence case.
13. Tests: Vitest (config caps workers at 4; never raise it). Playwright e2e via `npm run e2e` (one worker).

## Tasks

### Task 1: codec (`src/state/view-link.ts`)

Pure module, no React.

1. `type DecodedView` = the decoded, shape-validated view with full field names: `{ sourceKey: string | null; martId: string | null; record: Record<string, unknown> | null; search: string; contextIds: string[]; storageIds: string[] | null; folded: { sources: boolean; marts: boolean; data: boolean; row: boolean }; grid: GridState | null; dropped: number }`. Here `GridState` is from `src/state/store.tsx`, and `dropped` counts entries removed under rule 6.3.
2. `encodeViewLink(view: Omit<DecodedView, 'dropped'>): Promise<string>` returns the route `/v?s=…`, built per constraints 2–4. It doesn't enforce the length cap; the caller checks `route.length > MAX_ROUTE_LENGTH`.
3. `decodeViewLink(route: string | undefined): Promise<DecodedView | 'not-a-link' | 'unreadable'>`. Rules 6.1–6.3. It never throws. The route arrives percent-encoded (`ctx.route`), so take the `s` param with `URLSearchParams` and accept any extra params.
4. Export `MAX_ROUTE_LENGTH`.
5. Tests in `src/state/view-link.test.ts`:
   1. a round trip with native and joined columns (two prefixes), all filter value shapes (string, number, range object, relative preset), null sorts vs empty sorts, record, null grid;
   2. prefix sharing actually shortens the payload (the same column set with long join paths is shorter than without prefixes);
   3. each 6.2 case returns `'unreadable'`;
   4. each 6.3 case drops only that entry and counts it;
   5. a route that isn't `/v` returns `'not-a-link'`;
   6. a real-sized view (20 joined columns with ~120-character names, 4 filters) encodes under 2048.

   jsdom may lack `CompressionStream`. If so, polyfill it in `src/test-setup.ts` from `node:stream/web` + `node:zlib` (Node 18+ has a global `CompressionStream`; check before polyfilling).

### Task 2: resolving against the model, and the `applyView` action

1. `src/state/view-link-resolve.ts`: `resolveView(view: DecodedView, model: Model, readGrid: (martId: string) => Promise<Schema | null>): Promise<{ apply: AppliedView; skipped: Skipped }>`. Rules 6.4–6.7, 6.9, 6.10. `readGrid` returns the main mart's native schema plus joined fields (or null when it fails or times out; the caller wires the timeout). `AppliedView = { selection: Selection; grid: GridState | null; search: string; contextIds: string[]; storageIds: string[] | null; folded: DecodedView['folded'] }`. `Skipped = { mart: boolean; source: boolean; columns: number; filters: number; sorts: number; contexts: number; storages: number; entries: number }`. `entries` is `DecodedView.dropped`. Count those under "N columns" only when they were columns; otherwise fold them into the closest bucket. Simplest acceptable approach: count all of them under `columns` and say so in a comment.
2. `skippedMessage(skipped): string | null` per constraint 7.
3. Reducer action `{ type: 'applyView'; selection: Selection; grid: GridState | null; search: string; contextIds: string[]; storageIds: string[] | null }` in `src/state/store.tsx`. It replaces the selection, sets `grids[selection.martId]` when `grid` is non-null and `martId` is set, sets search/contexts/storages, and leaves `history` and `future` unchanged (no Undo entry). If the resolved selection has neither `martId` nor `sourceKey`, keep `selection` as `{ sourceKey: null, martId: null, record: null }` without `cleared`, so the first-load pick still runs.
4. Tests:
   1. `src/state/view-link-resolve.test.ts`: every 6.4–6.7, 6.9, 6.10 rule, the `readGrid` null path (grid passed through unpruned), and all columns dropped → grid null;
   2. `skippedMessage` wording, singular and plural, and order;
   3. reducer `applyView` in `src/state/store.test.ts`: no history entry, grids set only for the main mart.

### Task 3: wiring (SDK types, mock, App, header)

1. `src/sdk/types.ts`: add `readonly route?: string` to `Ctx`, and `copyLink?(path?: string): Promise<void>` to `ui`. Extend `_typeCheck` in `src/sdk/connect.ts` so it fails to compile if the SDK's shapes stop matching.
2. Mock (`src/sdk/mock/ctx.ts`): `route` is the `route` query param of the page URL (already URL-decoded by `URLSearchParams`), else `'/'`. `copyLink(path)` stores the path on `window.__copiedLink` and resolves. Also write it to `navigator.clipboard` when available, ignoring failures.
3. `src/ui/useViewLink.ts` (hook used by `AppBody`):
   1. decode `ctx.route` once on mount;
   2. once the model is loaded, resolve with `readGrid` built from `schemas.get` + `blendable.get` + the `withJoined` merge. Move `withJoined` from `MartGrid.tsx` into `src/api/blendable.ts`, export it, and import it in both places. Cap the wait at `VIEW_LINK_WAIT_MS` (add it to `src/config.ts`, 5000, 0 in test mode like `LOADED_HOLD_MS`);
   3. dispatch `applyView`;
   4. expose `{ pending: boolean; folded: DecodedView['folded'] | null; notice: string | null; dismiss(): void; copy(): Promise<void> }`. `copy` encodes the current store state plus the current folds (passed in by `AppBody`), then calls `ctx.ui.copyLink`, setting `notice` per constraint 10 on failure.
4. `src/ui/App.tsx`:
   1. While `pending`, count one more loading step and skip the first-load `init` dispatch.
   2. When the link's `folded` arrives, apply it to `folds` without calling `write`. Saved folds that arrive after must not override link folds. Merge so the link wins for this visit.
   3. Pass `onCopyLink` (only when `ctx.route !== undefined` and `ctx.ui.copyLink` exists) and `notice`/`onDismissNotice` to `Header`.
5. `src/ui/header/Header.tsx`: the chain button per constraint 10, and the notice line (role `status`, a close button labelled "Dismiss").
6. Tests:
   1. `src/ui/header/Header.test.tsx`: the button is shown/hidden and calls the handler; the notice renders and dismisses;
   2. a page-level test (follow the pattern in `src/ui/bands/page.test.tsx` with the mock ctx). A mock ctx whose `route` is a link to a known fixture mart with a filter, a sort and a joined column opens with that mart selected and those grid settings in the store. No `columnStore.save` and no preferences save happen on open. A link naming an unknown mart shows the notice and falls back to the first-load pick. An unreadable link shows the unreadable notice. Clicking the chain button calls `copyLink` with a route that decodes back to the current view.

### Task 4: e2e and docs

1. `e2e/smoke.spec.ts`: in mock mode, set up a view (pick a mart, add a filter, sort a column), click "Copy link to this view", read `window.__copiedLink`, open `/?mock&route=<encodeURIComponent(link)>` in a new page, and check that the same mart is selected and the same filter chip, sort arrow and columns are visible. A second test opens a link with an unknown mart id and checks the notice appears and the page is usable.
2. `README.md`: a short "Link to this view" section: what the link holds, the 2048 limit and the too-large message, what happens to parts the opener can't see, and that anyone holding the link can decode its filter values.
